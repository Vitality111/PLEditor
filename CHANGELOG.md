# PB — історія змін

Нотатки до кожної версії PB. Короткий опис інструмента — у README.md.

Конструктор базових варіацій Fiction Me та Cleaner без редагування коду.

## Запуск

З папки інструмента виконайте `npm start` і відкрийте http://127.0.0.1:4173.
Для використання інструмента не потрібно встановлювати залежності; вони потрібні для browser-тестів.

## Можливості

- Чотири шаблони Fiction Me: статичний фон із панеллю (00136/00138/00139), обкладинка зі скролом (00127–00131), зменшення hero під час скролу (00137), sticky-обкладинка (00140).
- П’ять композицій Cleaner: банер на фоні (00170), алерт (00165), банер з мокапом (00159), список, до/після. Порівняння містить демонстраційні асети — замініть обидва своїми.
- Набір варіацій 1 / 2 / 3 в одному креативі, імена файлів за схемою PlayableAds, експорт усіх варіацій одним ZIP.
- Завантаження PNG/JPEG/WebP/GIF, аудіо й шрифтів. Окремі portrait/landscape-асети.
- Додавання, перестановка, приховування та видалення блоків; редагування тексту, кольорів, типографіки й композиції.
- `**жирний**`, `[[виділення]]`, порожній рядок між абзацами. HTML у тексті не виконується.
- Живий preview для 8 пристроїв у двох орієнтаціях. Рух обкладинки відповідає вибраному шаблону.
- Локальне автозбереження через IndexedDB, undo/redo, дублювання, власні шаблони, переносний JSON із асетами.
- Один HTML із вбудованими асетами; перевірка бюджету 5 000 000 байтів. MRAID ready та CTA. Перша взаємодія не відкриває магазин; звук тільки після взаємодії, пауза при приховуванні.
- Перевірка 16 viewport-конфігурацій: CTA, document overflow, горизонтальне переповнення тексту, загрузка зображень, колізії Cleaner.

## Межі першої версії

Шаблони відтворюють сімейства композицій, а не всі старі CSS один до одного. Блоки розташовуються за правилами шаблону; довільного позиціювання по координатах немає. Немає Figma-імпорту, командного сховища, довільних ігрових механік та сертифікації для інших сіток. Preview ізолює креатив і не відкриває магазин. Автоперевірка не замінює візуальну перевірку та перевірку в AppLovin.

Асети взято як копії з папок користувача. Оригінальні креативи не змінені. Проєкти зберігаються окремо для кожного браузера й адреси інструмента. Для резервної копії використовуйте «Проєкт → Завантажити проєкт».


## Виправлення 0.1.1

Preview передає асети в ізольований iframe як data URL після завантаження з основної сторінки з її авторизацією. Це усуває зламані зображення на приватному хостингу. Файли кешуються під час поточної сесії, є повідомлення про помилку та повторне завантаження.

Мокап із `assetsForBuilder/Iphone 14.svg` використовується лише в редакторі. Рамка повертається для landscape; iframe зберігає вибраний розмір та пропорції. Рамку можна вимкнути, масштаб — змінити.

Бібліотека обмежена поточним шаблоном, його використаними асетами та завантаженнями цього проєкту. Поле конкретного елемента додатково відбирає файли за його роллю. Старі проєкти й використані завантаження зберігаються.

Регресійні тести завантаження й вибору асетів: `node --test tests/assets.test.mjs`.

## Редактор 0.2

Окремий вибір композиції та окремий екран редагування. Картки показують схему, опис руху та явну кнопку вибору. Зміна композиції має undo; попередні проєкти не видаляються. Власні композиції доступні на екрані створення.

Параметри зображення залежать від ролі: висота обкладинки в портреті, ширина колонки в ландшафті, масштаб і зсув hero у шаблоні зі зменшенням. Розмір тексту задається для конкретного блоку й орієнтації. Повзунки мають поле точного числового значення. Фон — окремий елемент. Файли шаблона заховані в додатковий вибір; основна дія — завантаження або заміна власного асета. Перестановка доступна тільки для блоків із вільним порядком.

Preview використовує браузерний CSS zoom замість transform над готовим iframe. Вибір 100% дає zoom=1 також із рамкою; оригінальні зображення не стискаються й не перемальовуються в canvas. Режим «Вписати» фізично зменшує креатив, тому для оцінки дрібних деталей використовуйте 100% або окремий preview. За дробового zoom viewport може відрізнятися на один CSS-піксель через округлення браузера; при 100% розмір точний.

Перевірено в браузері: 7 композицій × 16 розмірів без виявлених геометричних помилок; висота обкладинки 46→60%; масштаб hero 100→75%; скрол активує progress=1; iframe при 100% із рамкою має 393×852.

Підказка прокручування використовує оригінальні hand.png (130×340) і handL.png (245×297) з FictionME/00140/1. Емоджі видалено; редактор, окремий preview та експорт завантажують однакові асети.

При кожному відкритті або перезавантаженні стартує екран вибору Fiction Me / Cleaner та композиції. Збережений проєкт відкривається тільки через «Продовжити останній проєкт» або «Мої проєкти». Редактор прихований уже в початковому HTML, тому під час завантаження немає спалаху випадкової варіації.


## Позиції, напрямні та експорт 0.3

Кнопка «Переміщувати» вмикає перетягування в preview. X/Y — зсув від базової позиції у відсотках екрана, окремо для кожної орієнтації. «Скинути позицію» повертає поточну орієнтацію до шаблона. Лінійки показують логічні пікселі preview, рожеві напрямні — центр/краї екрана та центр/краї інших видимих блоків. Прив’язка спрацьовує в межах 6 логічних пікселів; Alt вимикає її. Координати підтримують автозбереження, undo/redo, переносний JSON і HTML-експорт.

Експорт працює в браузері: зображення перекодовуються у WebP з якістю 72 (можна змінити 50–100 або вимкнути), без зменшення роздільності, зі збереженням прозорості. Приймається результат тільки за економії щонайменше 10%. GIF і анімований WebP не перекодовуються; аудіо та шрифти вбудовуються без перекодування. CSS мініфікується Lightning CSS WASM, JS — Terser. HTML збирається в один файл; пробіли тексту/абзаци зберігаються. Після експорту є розмір до/після та перегляд стиснутих асетів. Оригінали для редактора та JSON залишаються незмінними.

Це браузерний варіант пайплайна `PlayableAds/inliner`: без локального Node/Sharp/FFmpeg і без сабсету шрифтів. Усі бібліотеки розміщені разом із сайтом; сторонніх CDN на експорті немає.

Виправлено панель «Текст на фоні»: нове центрування більше не сумується з успадкованим translate(-50%). Ширина тексту визначається внутрішньою шириною панелі, а не viewport.

Перевірки: `npm test` (14 регресійних перевірок); `npm run test:browser` (112 viewport-перевірок, експорт/імпорт, MRAID); `npm run test:interaction` (перетягування, напрямні, розділення орієнтацій, останній абзац панелі й стиснений HTML). Browser-тести запускають окремий headless Chrome і не керують відкритим браузером користувача.

Лінійки 0.3.1 винесені за весь фрейм/рамку телефону. Їхній нуль і поділки відповідають фактичному екрану креативу; цифри мають сталий розмір незалежно від zoom. Усередині iframe залишаються тільки напрямні. Підказка координат також показується ззовні, під рамкою. Перевірка: `npm run test:rulers` — 12 комбінацій орієнтації, рамки й масштабу.


## Імпорт плейблів 0.4

На стартовому екрані є «Завантажити плейбл · HTML / ZIP», у «Мої проєкти» — «Імпорт HTML / ZIP». Один HTML має містити вбудовані асети; ZIP — одну сторінку або єдиний index.html разом із CSS, класичним JS та асетами. ES-модулі з import/export спочатку потрібно зібрати inliner. Файл — до 30 МБ; розпакований ZIP — до 60 МБ і 1500 записів. Усі операції відбуваються в браузері, без передачі завантаженого плейбла на сервер.

Імпортований документ зберігає HTML/CSS та оригінальний JS. Редагуються DOM-тексти, їхній розмір/колір, зображення, ширина й позиції для обох орієнтацій. Вкладене текстове форматування зберігається при правках. Оригінальні ID/data-атрибути зберігаються; GUI використовує окремий простір data-studio-block та --studio-* для позицій. Лінійки, перетягування, прив’язка, undo/redo, IndexedDB і JSON працюють також для імпортованого документа. Порядок DOM зберігається. Canvas/SVG-графіку та UI, який створюється виключно JS, редактор не перебудовує.

У preview імпортованого HTML оригінальний JS, inline-обробники та вкладені iframe не виконуються: показуються макет і CSS-анімації; базове прокручування забезпечує довірений рушій редактора. Оригінальні скрипти та обробники залишаються у готовому HTML. JS-інтерактивність слід перевіряти на експортованому файлі.

Нові HTML-експорти містять application/json із налаштуваннями та SHA-256 маніфестом асетів. Видимі асети не дублюються; окремо вбудовуються лише відсутні в розмітці файли, потрібні для повторного редагування. HTML із цього конструктора відновлюється як нативний проєкт. Інші HTML та старі експорти відкриваються як редагований DOM. Дані імпортованого DOM також відновлюються при повторному імпорті HTML або JSON.

Перевірено: імпорт одиночного HTML, зміна тексту зі strong, заміна картинки, зсув із початковим translate(-50%), HTML/JSON round-trip, виконання збереженого JS у готовому файлі, ZIP із production cleaner/00159/1, нативний HTML round-trip. `npm run test:import`. Папка cleaner/test не використовувалася.


## Варіації, нові шаблони Cleaner і читабельний код 0.5

**Варіації.** Креатив має номер (наприклад, 00186) і варіації 1, 2, 3… Вгорі редактора — вкладки варіацій і «+ Варіація»: нова варіація є копією поточної, далі в ній міняють картинки або текст. Номер, мова, тип, референс і посилання магазинів спільні для всіх варіацій креативу. «Розкладку цієї варіації → усім» переносить розміри, позиції, кольори й порядок блоків, а картинки, фон і тексти кожної варіації не чіпає. Видалення варіації в «Мої проєкти» перенумеровує решту. «Новий креатив» бере наступний вільний номер. Стартовий проєкт першого запуску номер не займає.

**Імена файлів.** `{номер}_{варіація}_{clr|fcm}_{префікс}_{тип}_{мова}_{референс}_{код}_pl.html`, наприклад `00170_1_clr_am_kd_vt_nc_en__bn_pl.html` або `00165_2_clr_am_kd_vt_lz_pt_00124_alrt_pl.html`. Префікс `am_kd_vt` і код шаблону (`bn`, `alrt`, `ba`, `lr`) змінюються у вкладці «Експорт → Префікс і код шаблону». Імпортований файл із таким ім’ям отримує номер, варіацію і мову з імені; наступні файли того самого креативу стають його варіаціями.

**Експорт.** Якщо варіацій кілька, кнопка вгорі збирає ZIP: `00186/1/00186_1_…_pl.html`, `00186/2/…` — як папки в PlayableAds. Кожна варіація перевіряється окремо (CTA, HTTPS-посилання, номер, ліміт 5 МБ). «Тільки варіація N · HTML» експортує одну. «Завантажити проєкт» зберігає весь креатив з усіма варіаціями; при відкритті файлу номер зберігається.

**Cleaner.** Нові композиції «Банер на фоні» (00170/1: фон, текст-картинка, CTA) і «Алерт» (00165/EN/1: картка алерту з CTA всередині, примітка внизу). «Картинка і кнопка» перейменована на «Банер з мокапом» (00159). Виправлено: фон Cleaner тепер заповнює екран у ландшафті; картинка CTA більше не виходить за межі кнопки.

**Fiction Me.** Текст під кнопкою CTA тепер затемнюється на всю висоту зони CTA (рантайм міряє кнопку), тому кнопка не лежить на яскравому тексті на 320×480 і 480×320. «Картинка зі зменшенням» у ландшафті має колонку тексту 72%, як 00137.

**Код.** `dist/` перейменовано на `app/` — це і є вихідний код, без збірки. Код відформатовано (Prettier, `npm run format`). Логіка варіацій — `app/variations.js`, геометричні перевірки — `app/layout-checks.js` (спільні для редактора й тестів).

## Для розробника

- `npm start` — локальний сервер на 4173.
- `npm test` — швидкі тести (20).
- `npm run test:all` — усе: швидкі тести, 144 перевірки розмірів, взаємодія, лінійки, варіації та ZIP, імпорт. Сервер піднімається сам.
- `npm run screens [-- banner alert]` — скріншоти композицій у `test-results/screens` (сервер має бути запущений).
- Браузер для тестів: змінна `CHROME_PATH`, інакше встановлений Chrome (Windows/macOS), інакше Chromium з Playwright.
- Тест імпорту бере `cleaner/00159/1` з `PLAYABLE_ADS_ROOT` (за замовчуванням `../PlayableAds`).
- Новий шаблон: запис у `TEMPLATES` і гілка в `createProject` (`app/app.js`), назва й ескіз у `app/editor-model.js`, префікс асетів у `app/asset-scope.js`, CSS у `cleanerLayoutCSS` (`app/engine.js`) або у `fiction-renderer.js`, код для імені файлу в `app/variations.js`, джерело в `SOURCE_POLICY.md`.

## Затемнення тексту 0.5.1

У Fiction Me у списку елементів з’явився рядок «Затемнення тексту» (також кнопка у вкладці «Оформлення»). Окремо для верхнього й нижнього градієнта: «Як у шаблоні», «Своє» (колір, висота для портрета й ландшафту у % екрана або панелі, щільність) або «Вимкнено». ## Збереження в папці на диску 0.7

**Без пам'яті браузера.** У локальному запуску (`npm start`) проєкти, варіації, «мої композиції» й завантажені файли зберігаються в папці `workspace` поруч із програмою: `workspace/projects/*.json` (кожна варіація — невеликий JSON), `workspace/assets/` (картинки, шрифти, звук звичайними файлами), `workspace/state.json` (що було відкрито). Браузер нічого не зберігає. Інша папка: `PLAYABLE_WORKSPACE=D:\PLB\workspace npm start`. Шлях видно в консолі після запуску і в підказці внизу лівої панелі.

**Перенесення.** Проєкти, які раніше лежали в браузері, при першому запуску 0.7 автоматично переносяться в `workspace`, після чого копія в браузері видаляється. Папку `workspace` можна копіювати, бекапити або класти в спільний диск; у git вона не потрапляє (`.gitignore`).

**Онлайн-демо** (артефакт) працює без сервера, тому там проєкти й далі в браузері.

**Логотип** веде на головний екран (вибір продукту → шаблони); «Назад до редактора» повертає до відкритого креативу.

Тести: кожен браузерний набір запускає свій сервер із порожньою тимчасовою папкою; `tests/storage.mjs` перевіряє файли на диску, відновлення після перезавантаження, експорт, окремий preview і перенесення з браузера.

## Режим «Тест» 0.7.1

У редакторі над preview є перемикач **Редагувати / Тест**. «Редагувати» — як раніше: клік по елементу відкриває його налаштування, скрипти креативу не виконуються. «Тест» — креатив працює як на телефоні: власний JavaScript, анімації, переходи екранів (AI-чат: «Get the answer» → відповідь → CTA), кліки. Магазин не відкривається: натискання CTA показує підказку з посиланням. Креатив виконується в ізольованому iframe без доступу до студії й папки `workspace`. «Відкрити preview ↗» для імпортованих креативів теж запускає їх повністю.

Обмеження: елементи, які скрипт креативу створює вже під час гри (наприклад другий екран AI-чату з відповіддю і кнопкою), не з'являються в списку «Елементи», тому їх поки не можна замінити чи зробити кнопку кодом.
